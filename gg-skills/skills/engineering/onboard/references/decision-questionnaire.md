# 도입 결정 질문서 (Q1~Q10)

기존 프로젝트 도입(`SKILL.md` 「기존 프로젝트 도입」 Step 1)에서 **시작 시 한 번에** 묻는 질문이다. 스킬은 먼저 프로젝트의 `CLAUDE.md`·`AGENTS.md`·`.claude/rules/` 와 Step 0 측정 결과를 읽어 후보 답을 채워 보여 주고, 사용자는 항목마다 `맞음` 또는 수정만 답한다. 규칙 줄은 `--adopt` 의 「프로젝트 규칙 인용」 절을 쓴다.

답은 계획서 첫 장 「고정 결정」 표로 박는다. 이후 이 표와 충돌하는 지시가 나올 때만 멈춰 묻는다. 후보 답을 찾지 못한 항목은 지어내지 말고 `미확인`으로 둔다.

| # | 질문 | 미리 채우는 후보 답 (출처) | 계획에 미치는 영향 |
|---|---|---|---|
| Q1 | 진행·현재/다음 작업·우선순위의 SSOT 는 어디인가? | 프로젝트 규칙 중 진행·이슈 관리 책임을 적은 줄 | 계획서에 일정·진행·담당을 쓰지 않는다. 비차단 발견은 SSOT 의 백로그로 보낸다 |
| Q2 | 머지 권한과 흐름은? (작업 브랜치 → 검증 → PR → 누가 머지) | `브랜치`·`PR`·`머지` 가 든 규칙 줄 | PR 단위와 승인 지점을 채운다. 에이전트는 머지하지 않는다 |
| Q3 | 배포·운영 문구 중 계획에 영향 주는 것은? (예: 기본 브랜치 push 가 곧 배포) | `배포`·`운영`·기본 브랜치명이 든 줄 | 컷오버 PR 을 분리하고 머지 시각을 제한한다 |
| Q4 | 금지선은? (규칙 파일 자기 수정, 운영 DB 쓰기, force push, 대량 재작성 등) | `금지`·`⛔`·`force`·`--no-verify` 가 든 줄과 기존 훅이 막는 것 | 해당 파일은 계획에서 빼거나 "사용자 직접 수정"으로 표시한다 |
| Q5 | 서버 접점은? (타이머·cron·배포 대상, 발화 시각, 컷오버 가능 시간대, 롤백 방법) | `--impact` 의 운영 접점 걸림. 서버 쪽 값은 `미확인` | 서버 접점이 있으면 위험 체크리스트(`adopt-playbook.md`)를 적용한다 |
| Q6 | 구조 변경(폴더 이동·분리·개명)을 허용하는가? 허용 범위는? | `--adopt` 의 코드·폴더 레이아웃 절 | `no` 면 구조 변경 Phase 를 계획에서 빼고 매핑표만 만든다 |
| Q7 | 유지/삭제 판단 기준은? (참조된 파일은 이동 금지, 낡은 후보는 삭제 vs 보관, 대량 재작성 금지 범위) | `--structure` 분류, `docs/ADOPTION.md` 의 지킬 것 | 문서 이동·삭제 PR 의 기본 동작 |
| Q8 | 하네스 틀에서 의도적으로 제외하는 것은? (이유 포함) | `--structure`·`--catalog` 의 `없음`·`확인` 목록 | 완료 판정에서 "의도적 제외"로 따로 센다 |
| Q9 | 검증 명령과 필수 통과 항목은? | `CLAUDE.md` 의 검증 명령 절 | 각 PR 의 완료 기준 |
| Q10 | 하네스 정본 위치(템플릿 원본)는? | `sources.yaml` 의 `harness:` | 틀 비교 기준 |

## 보여 줄 문안

```
[고정 결정 초안 — 항목마다 맞음/수정으로만 답해 주세요]
Q1 <후보 답> (CLAUDE.md:<줄>) ........ 맞음?
Q2 <후보 답> (CLAUDE.md:<줄>) ........ 맞음?
...
미확인: <스크립트·문서로 알 수 없는 것>
```

답이 오면 「고정 결정」 표를 계획서 맨 앞에 넣고 Step 2 로 넘어간다.
