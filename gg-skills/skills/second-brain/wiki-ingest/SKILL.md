# wiki-ingest — 원본을 위키에 통합

이 스킬은 폴더를 새로 만들지 않는다. **`WIKI_SCHEMA.md`가 있는 위키 폴더**에서 실행한다. 없으면 멈추고 "위키 폴더가 아닙니다. 빈 틀은 gggmlduswjs/wiki-template"이라고 알린다.

## 0. 준비 (매번)

1. `WIKI_SCHEMA.md`를 **먼저 읽는다.** 구조·프론트매터·작성 규칙·거버넌스가 전부 거기 있다. 이 스킬과 충돌하면 스키마가 우선한다.
2. `wiki/index.md`와 `wiki/log.md`를 읽어 지금 위키에 무엇이 있고 무엇이 이미 반영됐는지 파악한다(중복 생성 방지).

## 1. 대상 정하기

- 사용자가 파일을 지정하면 그것만 한다.
- 지정이 없으면 `raw/`에서 위키에 아직 반영되지 않은 파일(`log.md`의 `[INGEST]`나 어떤 페이지의 `sources`에 경로가 없는 것)을 목록으로 보여 주고 **어느 것부터 할지 묻는다.** 기본은 **한 번에 한 건**이다. 여러 건을 한꺼번에 하라고 하면 한 건씩 순서대로 처리하되 건마다 결과를 요약한다.
- `raw/`는 읽기만 한다. 수정·삭제하지 않는다.

## 2. 읽고 핵심 말하기

- 원본을 끝까지 읽는다. 이미지가 있으면 텍스트를 먼저 읽고, 필요한 이미지만 `raw/assets/`에서 따로 열어 본다(이미지에서 읽은 내용은 "(이미지에서)"로 표시).
- 사용자에게 핵심 3~5줄을 먼저 말한다. 사용자가 강조할 것을 정해 주면 그에 따른다.

## 3. 쓰기

1. **출처 요약 페이지:** `wiki/sources/<kebab-case>.md` (`type: source`). 담긴 내용 요약, 원본 경로, 이 출처가 반영된 페이지 링크 목록.
2. **엔티티 페이지:** 원본에서 개념·인물·도구를 뽑는다. 각각 `index.md`에서 이미 페이지가 있는지 확인한다.
   - **있으면 병합.** 덮어쓰지 않는다. 새 출처의 관점을 `출처별 관점`에 추가하고, `sources`·`updated`를 갱신하고, 근거가 쌓이면 `status`를 올린다(stub → draft → solid).
   - **없으면 새로 만든다.** `concepts/` `people/` `tools/` 중 알맞은 폴더에 스키마의 프론트매터와 본문 틀로.
3. 한 건이 보통 여러 페이지(출처 요약 1 + 엔티티 몇 개)를 건드린다. 그래도 **새 페이지는 꼭 필요한 것만** 만든다. 확신이 없으면 stub로 둔다.
4. 본문에서 언급되는 다른 엔티티는 `[[링크]]`로 연결한다. 모든 주장에 가능하면 출처 요약 페이지를 링크한다.
5. **모순:** 기존 내용과 충돌하면 지우지 않고 해당 페이지 `## 모순/주의`에 두 출처를 모두 적는다.
6. 규칙: 한국어, 원문 복붙 금지(핵심만 압축), 추측은 "(추론)", 수치에는 단위·기준일·출처.

## 4. 마무리 (반드시)

- `wiki/index.md`: 새 페이지를 카테고리(Concepts / People / Tools / Sources)별로 한 줄 요약과 함께 추가한다. 갱신한 페이지의 요약이 바뀌었으면 고친다.
- `wiki/log.md`: 맨 아래에 한 줄 추가 — `- YYYY-MM-DD [INGEST] <원본 경로> → 신규 N(이름들), 갱신 N, 모순 N`.
- 사용자에게 보고: 만든 것·갱신한 것(경로), 발견한 모순, 사람이 판단할 것.
- **커밋하지 않는다.** 커밋은 사용자가 요청할 때만 한다.

## 하지 않는 것

- `raw/` 수정, 페이지 삭제·`_archive/` 이동(제안만 한다)
- 개인정보·인증정보를 위키에 옮기는 것(발견하면 옮기지 말고 보고)
- 스키마에 없는 폴더 만들기
