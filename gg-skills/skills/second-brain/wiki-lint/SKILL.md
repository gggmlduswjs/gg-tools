# wiki-lint — 위키 건강검진

**`WIKI_SCHEMA.md`가 있는 위키 폴더**에서 실행한다. 없으면 멈추고 알린다. **점검과 보고만 하고, 고치기 전에 승인을 받는다.**

## 점검 항목

가능한 것은 명령으로 **기계적으로** 센다(링크·index는 추측하지 않는다). 해석이 필요한 것만 읽고 판단한다.

| 분류 | 항목 | 방법 |
|---|---|---|
| 구조 | 깨진 `[[링크]]` | 모든 `[[이름]]`이 가리키는 파일이 있는지 |
| 구조 | 고아 페이지 | 어느 페이지에서도 링크되지 않는 페이지(`index.md`의 링크는 세지 않는다) |
| 구조 | index 불일치 | 페이지는 있는데 `index.md`에 없음 / 있는데 파일이 없음 |
| 구조 | 프론트매터 누락 | `type` `title` `status` `created` `updated` `sources` |
| 내용 | 방치된 stub | `status: stub`인데 오래 갱신되지 않음 |
| 내용 | 모순 | 페이지끼리 충돌하는 주장(`모순/주의`에 이미 표시된 것은 "표시됨"으로 구분) |
| 내용 | 낡은 주장 | `updated`가 오래됐거나 더 새 출처가 대체한 내용 |
| 내용 | 빠진 개념 | 여러 페이지에서 언급되는데 자기 페이지가 없는 중요한 개념 |
| 거버넌스 | 죽은 노드 후보 | 6개월 이상 갱신·참조가 없음 / 고아 / 새 노드가 나왔는데 `대체됨` 표시 없이 남음 (`WIKI_SCHEMA.md` 거버넌스 기준) |
| 거버넌스 | 민감 정보 | 인증정보·개인정보로 보이는 문자열 |
| 확장 | 메울 수 있는 빈칸, 다음에 조사하거나 구할 만한 질문·자료 | 읽고 제안 |

`raw/`에 아직 반영되지 않은 파일이 있으면 그 목록도 보고한다(ingest 대기).

## 보고 형식

1. **한 줄 총평:** 페이지 수, 항목별 문제 개수.
2. 항목별 목록(파일 경로와 한 줄 설명). 문제가 없는 항목은 "없음".
3. **사람이 판단할 것:** 모순 해소, 삭제·`_archive/` 이동 제안, 새 페이지로 만들 개념, 조사할 질문.
4. 바로 고칠 수 있는 것(깨진 링크 정리, index 갱신 등)은 **"고칠까요?"** 로 묻는다.

## 승인 후에만

- 승인받은 항목만 고친다. 고친 뒤 `wiki/log.md`에 `- YYYY-MM-DD [LINT] 점검 N건, 수정 N건` 을 추가한다.
- 삭제·이동은 승인을 받아도 **지우지 않고 `_archive/`로 옮긴다.**
- `raw/`는 건드리지 않는다. 커밋은 사용자가 요청할 때만 한다.
