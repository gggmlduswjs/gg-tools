# harness-audit — 6축 진단

**출력은 "강의 요약"이 아니라 "우리가 아직 안 한 것 + 근거"다.** 요약을 뱉으면 이 스킬은 실패한 것이다.

프레임 출처: 실리콘밸리 엔지니어의 Claude Code 강의 6축(구조·맥락·계획·실행·검증·개선).
축별 판정 기준 = `references/six-axes.md` · 강의 원문 위치 = `references/course-map.md`.

## 절차

### 0. 기존 자산부터 조회 (건너뛰지 말 것)

**이 단계를 건너뛰면 이미 있는 걸 또 만들라고 추천하게 된다.** 실제로 그 사고가 있었다 —
2026-07-28 이 스킬을 만들 때, 강의 내용의 70%가 이미 스킬로 존재하는 걸 뒤늦게 발견했다.

```bash
ls ~/.claude/skills/ && ls .claude/skills/ 2>/dev/null
ls .claude/rules/ .claude/hooks/ .claude/agents/ 2>/dev/null
cat .claude/settings.json 2>/dev/null | head -40
ls .dev/harness/ docs/adr/ 2>/dev/null
```

`references/course-map.md` 의 "이미 스킬로 구현됨" 열과 대조한다. 덮인 축은 **판정만 하고 새 제안 금지.**

### 1. 축별 실측

`references/six-axes.md` 의 항목을 레포에서 직접 확인한다. **읽지 않고 판정하지 않는다.**
구조·맥락 축에 정량 점수가 필요하면 `ai-readiness-cartography` 를 쓴다 — 여기서 재구현하지 않는다.
최근 결과(`docs/ai-readiness-map.html` 등)가 있으면 재실행 말고 읽는다.

### 2. 판정 3단계

| 판정 | 조건 | 출력 의무 |
|---|---|---|
| **있음** | 자산이 존재하고 최신 | **경로를 근거로 제시.** 경로 없이 "있음" 금지 |
| **없음** | 자산이 없음 | 없어서 **실제로 나는 손해**를 한 줄. 못 대면 제안하지 않는다 |
| **썩음** | 있는데 코드와 어긋남 | 어긋난 지점을 실측 근거로 |

### 3. staleness 를 반드시 볼 것 — 이 스킬의 고유 몫

다른 스킬은 자산이 **있는지**만 본다. 자산이 **맞는지**는 아무도 안 본다.
강의 Part 3 Ch01 §4-2: *"코드베이스가 바뀌면 CLAUDE.md 설명이 틀어지고 스킬 가정이 사라진다."*

```bash
# 컨텍스트가 인용한 경로가 실존하나 (레포에 검증 스크립트가 있으면 그걸 쓴다)
ls _scripts/check_context_paths.py 2>/dev/null && python _scripts/check_context_paths.py
# 스킬·룰이 인용한 명령/경로가 아직 사나 — 샘플로 직접 확인
# CLAUDE.md 가 마지막으로 갱신된 시점 vs 코드
git log -1 --format=%ci -- CLAUDE.md && git log -1 --format=%ci -- src/
```

### 4. 출력 — 빈 칸만, ROI 순

```
축별 판정 표 (6행, 근거 경로 포함)
그다음: 빈 칸 · 썩은 자산만 ROI 순. 각 항목 = 무엇 / 왜 손해 / 얼마나 걸림(S<1h·M 1-4h·L 4h+)
```

**축별로 다 채우려 하지 말 것.** 강의에 있다는 건 근거가 아니다. 이 레포에서 손해가 나는 지점만 낸다.

## 하지 말 것

- **강의 내용 요약해서 늘어놓기.** 사용자는 강의를 봤다. 필요한 건 대조 결과다.
- **이미 있는 자산의 재구현 제안.** 0단계를 했으면 안 나온다.
- **"6축을 다 채우자"** — 강의 Ch04 §7-2 는 정반대를 말한다: *"좋은 하네스는 점점 단순해진다. 안 쓰는 건 치운다."*
  안 쓰는 자산을 **지우자는 제안**도 유효한 출력이다.
- **없는 손해를 지어내기.** 손해를 한 줄로 못 쓰면 그 항목은 빼라.
