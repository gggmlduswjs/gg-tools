# 클로바노트/에이닷 회의록 자동화 (구글드라이브 연동)

구글드라이브 "회의" 폴더(ID: `1VXJt5J1p3aTzGnUpvhO6-8ZGqEUla-rP`)에 쌓이는 클로바노트/에이닷 통화 텍스트 파일을 읽어서 (1) 정해진 양식의 회의록으로 정리하고, (2) 액션 아이템을 구글 캘린더에 등록하고, (3) 완성된 회의록을 Gmail 초안으로 만들고, (4) 처리된 원본 파일은 "완료" 하위폴더로 이동시키는 스킬.

## 전제 조건 / 한계
- 완전 무인 자동화(파일 업로드 → 자동 트리거)는 이 환경에서 불가능하다. 사용자가 대화를 열고 이 스킬 실행을 요청해야 시작된다 (예: "회의 폴더 확인해줘"). 그 요청 이후 폴더 스캔부터 캘린더 등록·메일 초안까지는 전부 자동으로 처리된다.
- 캘린더 일정 생성, Gmail 초안 생성, 드라이브 파일 이동은 모두 사용자 계정에 실제 변경을 가하는 행동이므로, **반드시 최종 확인을 받은 뒤에만 실행**한다. 회의록 초안과 추출된 액션 아이템을 먼저 채팅에 보여주고, 사용자가 확인/수정한 뒤에 캘린더·Gmail·드라이브 이동을 실행한다.
- 폴더 ID가 바뀌었거나 못 찾으면 `Google Drive:search_files`로 `name = '회의' and mimeType = 'application/vnd.google-apps.folder'`를 검색해서 재확인한다.

## 워크플로우

### 0단계: 처리 대상 파일 찾기
1. `Google Drive:search_files`로 `'1VXJt5J1p3aTzGnUpvhO6-8ZGqEUla-rP' in parents`를 검색해 "회의" 폴더 안의 항목을 나열한다.
2. 그중 이름이 "완료"인 하위폴더는 제외한다. 하위폴더가 없으면 나중에(5단계) 만들면 된다.
3. "완료" 하위폴더가 이미 있다면 그 폴더 ID도 기억해두고, 그 폴더 안에 있는 파일은 이미 처리된 것이므로 건너뛴다.
4. 나머지 파일들이 이번에 처리할 대상이다. 대상이 없으면 "새로 처리할 회의 파일이 없어요"라고 안내하고 종료한다.
5. 파일이 여러 개면 하나씩 순서대로 처리한다 (사용자에게 몇 개 발견했는지 먼저 알려준다).

### 1단계: 내용 읽기 및 파싱
`Google Drive:read_file_content` 또는 `download_file_content`로 파일 내용을 가져온다.
- 클로바노트 형식: `화자라벨  00:00:05` 다음 줄에 발화 내용. 화자 라벨은 원문 그대로 유지 (임의로 실제 이름 변환 금지).
- 에이닷 통화 텍스트는 형식이 다를 수 있음 — 통화자/타임스탬프 구분자가 다르면 유연하게 파싱하되, 화자 구분과 시간 흐름은 최대한 보존한다.
- 파일에 AI 자동 요약/할 일 섹션이 포함되어 있으면 참고자료로만 활용하고 본문에 그대로 복사하지 말 것 (재구성해서 반영).

### 2단계: 회의록 작성
`assets/template.md` 양식을 그대로 따른다. 안건별 논의 내용, 결정 사항, 액션 아이템(담당자/할 일/마감일)을 정리한다. 마감일이 스크립트에 명시되지 않으면 "미정"으로 두고 다음 단계에서 사용자에게 확인한다.

**정확도 규칙 (가장 중요)**
- STT 특성상 클로바노트/에이닷 텍스트에는 오인식이 많다. 애매하거나 맥락이 불분명한 발언을 그럴듯하게 매끄러운 문장으로 지어내서 채우지 않는다. 문장이 이해되지 않으면 이해되지 않는 채로 둔다.
- 원문 시간대(타임스탬프)와 화자 라벨을 인용하며 정리한다 — "참석자1이 ~라고 말함(00:59)" 식으로, 무슨 근거로 이렇게 정리했는지 역추적 가능하게 쓴다. 시간대 없이 뭉뚱그린 요약만 내지 않는다.
- 회의록을 "확인된 사실"과 "불확실한 부분"으로 나눈다. 같은 단어가 통화 중 여러 번 다르게 오인식된 것 같으면(예: 같은 고유명사가 매번 다른 발음으로 적힘) 이를 추정이라고 명시하고 확정하지 않는다.
- 화자의 역할(내부 직원/거래처/학교 등)이 원문에 명시되지 않았으면 "~로 추정"이라고 반드시 표시하고, 확정된 사실처럼 서술하지 않는다.
- 통화/회의가 정돈된 안건 중심이 아니라 산발적인 문제 확인·트러블슈팅 성격이면, 안건/결정사항 틀에 억지로 끼워 맞추지 말고 "문제 상황 → 확인된 사실 → 불확실한 부분 → 다음 조치" 흐름으로 유연하게 재구성해도 된다. 양식은 참고 기준이지 절대 규칙이 아니다 — 원문 왜곡보다 양식 이탈이 낫다.
- 완성 후 스스로 점검: 회의록의 각 문장이 원문의 특정 발언에 근거하는가? 근거 없이 매끄럽게 다듬은 문장이 있다면 다시 원문을 보고 고친다.

완성된 회의록 초안을 채팅에 보여준다.

### 3단계: 액션 아이템 확인
액션 아이템 목록과, 이를 캘린더에 어떻게 등록할지(제목/날짜/시간) 정리해서 사용자에게 보여주고 확인을 받는다.
- 마감일이 명확하면 해당 날짜의 종일 일정(allDay: true)으로 등록.
- 시간이 명시되어 있으면 해당 시간대에 1시간짜리 일정으로 등록.
- 마감일이 불명확하면 사용자에게 날짜를 물어보거나, 회의 다음 영업일로 임시 지정할지 확인한다.
- 이벤트 제목 형식: `[할일] {담당자} - {할 일 내용}`
- description 필드에 원 회의명과 회의록 링크(또는 요약)를 넣는다.

확인 후 `Google Calendar:create_event`를 액션 아이템별로 호출한다.

### 4단계: Gmail 초안 생성
회의록이 확정되면 `Gmail:create_draft`로 사용자 본인 앞으로 초안을 만든다 (to는 사용자 본인 이메일; 참석자에게 보내고 싶다면 먼저 물어본다).
- 제목: `[회의록] {회의명} - {날짜}`
- 본문(body): 완성된 회의록 전체 (마크다운이 아니라 읽기 좋은 일반 텍스트로 변환해서 넣는다 — 헤더는 굵게 강조하는 정도로만).
- 액션 아이템 표도 본문에 포함한다.
- 초안만 생성하고 발송은 하지 않는다 (Gmail 도구 자체가 발송을 지원하지 않음). 초안 생성 후 사용자에게 "Gmail 초안함에 저장했어요. 확인 후 발송해주세요"라고 안내한다.

### 5단계: 처리 완료 표시
- "완료" 하위폴더가 아직 없으면 `Google Drive:create_file`로 mimeType `application/vnd.google-apps.folder`, parentId를 "회의" 폴더 ID로 지정해 생성한다.
- 방금 처리한 원본 파일을 `Google Drive:update_file`(parentId를 "완료" 폴더 ID로 지정)로 이동시킨다.
- 폴더에 처리 대상 파일이 더 남아 있으면 1~5단계를 다음 파일에 대해 반복한다.

### 6단계: 결과 요약
모든 파일 처리가 끝나면 사용자에게 다음을 요약해서 알려준다:
- 이번에 처리한 파일 개수와 이름
- 등록된 캘린더 일정 개수와 목록
- 생성된 Gmail 초안 제목 목록
- 다음에 확인이 필요한 사항 (예: 마감일 미정 액션 아이템)

## 참고
- 회의록 양식 상세: `assets/template.md`
- 참석자 이름을 실제 이름으로 바꾸지 말 것 (사용자가 원 라벨 유지를 선택함)
- 클로바노트 자동 요약은 참고만 하고 그대로 붙여넣지 말 것
