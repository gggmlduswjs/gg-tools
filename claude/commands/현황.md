현재 프로젝트의 "이해 현황"을 브라우저에 띄운다. **코드가 바뀌었으면 강의를 먼저 갱신**한 뒤 연다.

## 절차

1. **코드 변경 여부 판단** (강의는 코드 따라 낡으므로):
   - 현재 커밋: `git -C "<프로젝트루트>" rev-parse HEAD` (git 아니면 이 단계 건너뛰고 3번으로).
   - 마커 파일 `<프로젝트루트>/.understanding-built-at` 의 내용과 비교. 파일 없으면 "바뀜"으로 간주.

2. **바뀌었으면 → 무거운 아티팩트 재생성** (이 컨텍스트에서 직접, 백그라운드 헤드리스 쓰지 말 것 — 잘 깨짐):
   - 먼저 사용자에게 "코드가 바뀌어서 강의를 다시 만드는 중(몇 분 걸림)"이라고 알린다.
   - **codebase-to-course** 스킬로 이 프로젝트의 `*-course` 강의를 최신 코드로 재생성한다(기존 폴더 덮어쓰기).
   - (선택) 아키텍처가 크게 바뀌었으면 `/omm-scan`, `/ai-readiness-cartography` 도 갱신.
   - 끝나면 현재 커밋 해시를 `<프로젝트루트>/.understanding-built-at` 에 기록(다음엔 안 바뀌었으면 스킵).
   - **안 바뀌었으면 이 단계 전체를 건너뛴다** (재생성 금지 — 토큰·시간 낭비).

3. **런처 실행**(현재 아티팩트를 브라우저 탭으로 엶):
   ```
   powershell -ExecutionPolicy Bypass -File "C:\Users\user\.claude\understand-any.ps1"
   ```
   → 파일트리 맵 갱신 + omm(.omm 있으면) + AI-준비도 + 강의 + 파일트리 를 브라우저로 연다.

4. 런처 출력의 현황 요약 + (재생성했으면) "강의 갱신 완료"를 사용자에게 짧게 전달한다.

## 핵심 규칙
- **코드 변경 없으면 재생성하지 않는다** (즉시·공짜). 변경 있을 때만 강의를 다시 만든다.
- 재생성은 헤드리스가 아니라 **이 대화 컨텍스트에서 직접** (안정성).
- `.understanding-built-at` 마커는 gitignore 대상(로컬 전용).
