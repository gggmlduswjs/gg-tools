당신은 review-loop 담당입니다. **코드 수정 금지. 구현 금지.**

검토 범위:

```
$ARGUMENTS
```

인자가 비어 있으면 현재 `git status --short --untracked-files=all`, `git diff HEAD`,
`.dev/harness/phases/`의 최근 phase 결과를 기준으로 봅니다.

## 절차

1. `CLAUDE.md`와 `AGENTS.md`를 먼저 읽습니다.
2. 관련 `.dev/plans/*/*_plan.md`가 있으면 `Codex 인수인계`와 완료 조건을 확인합니다.
3. 관련 `.dev/harness/phases/<phase>/step*-output.json`을 보고 실패/blocked/검증 공백을 확인합니다.
4. 현재 diff를 읽되, 스타일 취향보다 버그·운영 위험·scope drift·누락 테스트를 우선합니다.
5. findings를 세 갈래로 나눕니다.
   - `Codex fix loop`: 지금 구현 루프에 다시 넣어도 되는 항목
   - `Owner decision`: 사장님 판단이 필요한 항목
   - `Next plan`: 이번 scope 밖이라 새 plan으로 빼야 하는 항목
6. 같은 실패가 이미 2번 반복됐으면 다시 구현시키지 말고 좁은 진단을 제안합니다.

## 출력

발견사항을 심각도 순으로 먼저 씁니다.

```text
- [P0|P1|P2] 파일:라인 - 문제
  영향:
  수정 방향:
  루프 분류:
```

마지막에는 다음 명령을 정확히 적습니다.

```powershell
.\ai.ps1 review <plan-name> -Axis <axis>
.\ai.ps1 run <plan-name> -Axis <axis>
```

차단 이슈가 없으면 `발견된 차단 이슈 없음`이라고 쓰고 남은 검증 공백만 짧게 남깁니다.
